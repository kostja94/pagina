# Page Construction Workflow

Use this workflow for a new individual page. Scale the depth to page complexity and risk.

## 1. Establish Context

Inspect the active project context, route and origin, entry paths, continuation paths, neighboring pages, audience, primary task, content source, data requirements, locale and market scope, framework, rendering model, design system, shared layout, and existing components.

Separate page-local decisions from site-wide architecture. Escalate only when the page cannot be correct without changing global navigation, routes, or product behavior.

## 2. Define The Page Contract

State the page's purpose, audience, primary task, essential information, actions, states, inputs, outputs, and exclusions. Confirm which claims and assets have reliable sources. Ask for missing facts that block complete, honest copy rather than omitting the corresponding content.

## 3. Shape Information Hierarchy

Order content by what users need to recognize, evaluate, do, and verify. Use sections because they serve the page task, not because a familiar template contains them. Distinguish visible sections from technical component boundaries.

## 4. Compose Existing Components

Reuse the target project's layout, navigation, controls, sections, tokens, and content primitives. Add a component only when the page has a real unmet responsibility. Do not create a parallel design system.

## 5. Implement In Place

Follow project conventions for routing, data loading, metadata, localization, analytics, forms, errors, tests, and file organization. Preserve stable URLs and existing product behavior unless the request explicitly changes them.

Add only the smallest page-local API, adapter, schema, content source, or submission handler needed for a truthful working page. Do not disguise a missing operational system with sample data.

## 6. Refresh Project Memory

Write durable facts confirmed during the task to the active project context. Archive a superseded value before replacing it and update the context date. Keep code and maintained project documents as the source of truth for detailed operational data.

## 7. Verify In Context

Exercise the actual route at representative desktop and mobile sizes. Check keyboard operation, focus, long and missing content, loading, empty, error, success, permissions, metadata, links, forms, and relevant automated tests. Inspect screenshots for visually significant work.
