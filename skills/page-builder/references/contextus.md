# Contextus Integration

[Contextus](https://github.com/kostja94/contextus) is the sole owner of durable organization, product, and project context. Pagina owns page construction and consumes that context; it does not define another memory model.

## With Contextus

Look for `contextus.md` at the target repository root. Read its overview and only the modules relevant to the page, such as product, audience, brand, website, marketing, technical, decisions, and constraints.

During page work:

- treat explicit user or team statements as confirmed updates;
- return agent research, code observations, and document interpretations as candidate facts with source locations;
- preserve lifecycle and visibility labels;
- do not load unrelated history by default;
- do not reorganize the full context system as a side effect of building one page.

Contextus maintenance and page implementation are separate permissions. Updating context does not authorize changing unrelated pages, and building a page does not authorize rewriting the complete context system.

## Without Contextus

Pagina must still complete a feasible page task. Read available repository documentation, legacy context files, and user-provided facts. Ask one concise question when missing information would materially change the page.

At completion, report durable facts and candidates that may deserve future maintenance. Do not create `project-context.md`, invent an archive, or establish a Pagina-specific context format.
